# HyperDB engineering roadmap

Status is based on the working tree inspected on 2026-10-20. Pre-existing uncommitted changes remain in place.

| Milestone | Outcome and prerequisites | Main interfaces | Acceptance and verification | Status / risk |
| --- | --- | --- | --- | --- |
| 1. Read-only SQL slice | Turn lexer and in-memory tables into a working query path. | parser AST, executor, CLI | Projection, predicates, ordering, limits, errors, and end-to-end tests. | **Complete** for the documented subset. |
| 2. Storage invariants | Control mutation of registered tables and retain invariants under row replacement. | `Database`, `Schema`, `insert_row`, `replace_rows` | Reject duplicate names, malformed row width, and NULL in required columns; retain index and embedding correctness after writes. | **Complete** for validated single-table writes; replacement rebuilds indexes and remaps embeddings. Affinity coercion is intentionally absent; snapshot persistence is covered in milestone 7. |
| 3. Relational breadth | Add one inner join and grouped aggregates. | AST, executor, aggregate module | Two-table join, qualified names, `COUNT/SUM/AVG/MIN/MAX`, `HAVING`, NULL cases, tests checked against representative SQLite fixture results. | **Complete** for this subset. Aliases, outer joins, multiple group keys, and general expressions remain. Nested-loop joins are a scaling risk. |
| 4. Index and measurement | Finish the B-tree, use it for equality, measure a reproducible workload. | `BTree`, `Database`, executor, benchmarks | Split/duplicate/index-update tests, scan/index result equivalence, Release benchmark and SQLite baseline. | **Complete** for equality lookups. Range scans, index-aware joins, and more workloads remain. |
| 5. AI and Python boundary | Add grounded vector retrieval and connect Python to the C++ SQL engine. | `VectorIndex`, local bridge, Streamlit | Exact cosine search with metadata filter; Python bridge test; live Spider fixture query. | **Partial.** Embeddings are caller-supplied; no approximate search or model accuracy evaluation. Bridge imports small tables per query. |
| 6. Insurance data workflow | Preserve local schema and source caveats; offer read-only inspection. | `data/`, `python/`, docs | CMS field dictionaries linked; local ZIP/CSV/SQLite equality verified by streaming every row. | **Partial.** Local copies match exactly, but the original CMS download revision and import procedure are not recorded; the third ZIP is invalid. |
| 7. Durable and broader engine | Save and reload state, then broaden SQL and mutation semantics from workloads. | `Database::save/load`, snapshot format, CLI, planner | Round-trip rows, schema, index definitions, embeddings; reject damaged files; then compare supported SQL behavior with a SQLite fixture. | **Partial.** Versioned snapshots and CLI reload work. SQL `CREATE TABLE`, `INSERT`, `UPDATE`, and `DELETE` work for one statement at a time. POSIX CLI writers serialize with an advisory lock. POSIX save syncs file and directory, but crash recovery is unverified. No WAL, library-level concurrency control, SQL index DDL (use `--index`), or broad SQL conformance yet; one differential fixture passes. |

Dependency order: 1 → 2 → 3/4 → 5 → 7. Milestone 6 can proceed independently. The next engineering priority is a broader conformance workload, measured mutation costs, and crash fault testing, with the Python/model contract kept explicit.
